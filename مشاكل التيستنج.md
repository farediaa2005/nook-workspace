## [BUG-003] Session is purely in-memory — page refresh forces re-login (no persistence)

**Severity:** Critical

**Category:** Authentication / UX

**Page:** All protected pages

**Viewport:** All

**Language:** All

**Theme:** All

**Steps to Reproduce:**

1. Login successfully
2. Navigate to Dashboard
3. Press F5 (browser refresh)

**Expected Result:**
User remains logged in; the session persists across refreshes.

**Actual Result:**
User is immediately redirected to `/auth/login`. All state (auth token, user data, active shift, loaded data) is lost because everything is stored in-memory signals with ZERO localStorage/sessionStorage persistence.

**Evidence:**

* `auth.service.ts` line 55-57: `restoreSession()` sets `accessToken = null` and `refreshToken = null` — explicitly zeroing tokens on construction.
* Comments throughout the codebase: "Pure in-memory state — ZERO localStorage / sessionStorage"

**Impact:**
**CRITICAL** — This is a fundamental usability blocker. No production application can function without session persistence. Every browser refresh, accidental navigation, or new tab opening forces a complete re-login and loss of all working state including active shift data, workspace sessions, and loaded data.

**Suggested Fix Direction:**
Store the `accessToken` and `refreshToken` in `localStorage` or `sessionStorage`. Restore them in `restoreSession()`. Optionally call `fetchCurrentUser()` on app initialization to rehydrate user data.

**Reproduction Status:** Reproducible (by design)

**Priority:** P0
